## Commands

Run commands from the repository root. The Taskfile is Linux-only.

| Command | Purpose |
|---|---|
| `task dev` | Start the Wails development loop with Vite HMR |
| `task build` | Build the production frontend and `bin/cadence` |
| `task run` | Run the built binary |
| `task test` | Build the frontend, run Go tests and Vitest |
| `task check` | Run Go vet, `svelte-check`, ESLint and Prettier |
| `task lint` | Run Go vet, ESLint and Prettier |
| `task format` | Check Go and frontend formatting |
| `task format:write` | Format Go and frontend sources |
| `task package` | Create AppImage, tar.gz and checksums in `bin/` |
| `task clean` | Remove build outputs and generated bindings |

The frontend scripts can also be run directly from `frontend/`:

```bash
npm ci
npm run check
npm run lint
npm run format
npm run test
npm run build
```

## Generated files

The following paths are generated and ignored by Git:

- `frontend/dist/` — Vite production bundle embedded into the Go binary.
- `frontend/node_modules/` — npm dependencies.
- `bin/` — compiled binary and release artifacts.
- `build/linux/cadence.desktop` and `build/linux/appimage/build/` — packaging outputs.

`frontend/bindings/` is generated by Wails from the Go services and is committed so a fresh checkout can type-check without a prior build. Regenerate it with:

```bash
wails3 generate bindings -clean=true -ts -i .
```

The binding generator is given the main package explicitly. It walks the Go dependency graph, so services in `internal/` packages are included without scanning `frontend/node_modules`.

## Go tooling note

An npm dependency ships a small Go package. A plain `go test ./...` therefore also visits `frontend/node_modules`. The Taskfile and CI filter that directory:

```bash
go test $(go list ./... | grep -v '/node_modules/')
go vet $(go list ./... | grep -v '/node_modules/')
```

Use `task test` and `task check` for the supported workflow.

## Wayland and Sway

Cadence is frameless and relies on its custom titlebar for dragging. Tiling compositors ignore the requested 420×220 size, so add a floating rule for the application ID:

```text
for_window [app_id="io.github.ivandec0.cadence"] floating enable
for_window [app_id="io.github.ivandec0.cadence"] resize set 420 220
```

The app sets `WebviewGpuPolicyOnDemand` for WebKitGTK. If rendering is broken on a particular driver, set `WebviewGpuPolicyNever` temporarily to isolate the issue.

### Native window resizing

Wails v3 beta.34 maps `Window.SetSize` to `gtk_window_set_default_size` on GTK4, which does not resize an already mapped window. The queue expansion therefore calls `internal/platform.WindowService`, a small cgo GTK4 helper that sets both a size request and the default size on the GTK main thread. If a later Wails release provides a real resize operation, remove the helper and the generated platform binding.

## Skin development

Development skins live in `skins-dev/<id>/`. Cadence scans that directory automatically when it runs from the repository root. Use `--skins-dev <dir>` for another location.

```bash
./bin/cadence --skins-dev ./skins-dev
./bin/cadence --safe-mode
./bin/cadence --demo
```

Manifest, layout, CSS and asset failures appear as warnings in the skin library. Restart Cadence after editing a development skin; packages are validated and scanned at startup. The included [`skins-dev/afterglow`](../skins-dev/afterglow) is a complete level 2 example.

Installed skins are stored under `$XDG_DATA_HOME/cadence/skins/<id>/`; settings are in `$XDG_CONFIG_HOME/cadence/config.json`. The built-in Clarity skin is native, cannot be removed, and is used when a declarative skin cannot be validated or mounted.

See [`skin-format.md`](skin-format.md) and [`skin-authoring.md`](skin-authoring.md).

## Spotify development

Spotify uses Authorization Code + PKCE with a fixed loopback callback:

```text
http://127.0.0.1:43821/callback
```

Set the public Client ID temporarily with:

```bash
export CADENCE_SPOTIFY_CLIENT_ID="your-client-id"
./bin/cadence
```

or paste it into the Spotify account panel opened from the **DEMO** / **CONNECT**
badge. The Client ID is stored in `$XDG_CONFIG_HOME/cadence/config.json`; the
refresh token is stored by the OS keyring and the access token stays in Go
memory.

Useful flags:

```bash
./bin/cadence --demo   # start with the simulated player even if a token exists
```

The account panel exposes reconnect, logout and demo/Spotify mode switching.
No token, authorization code or PKCE verifier is logged or sent to the
frontend. Register the exact redirect URI in the Spotify Developer Dashboard
before testing login. If port 43821 is occupied, authentication fails with a
clear message; do not silently choose another port.

Tests use `httptest` servers and an injected fake browser opener. The live
authorization callback and keyring restore are verified manually on Arch; a
playback test also needs the official Spotify desktop client logged in and
active as a Connect device.

## Architecture rules for v1

- The frontend never receives Spotify access tokens, refresh tokens or PKCE values.
- Spotify access tokens stay in Go memory; refresh tokens go to the OS keyring.
- The demo provider remains available through `--demo`.
- Album art is proxied/cached through Go; skins and CSS cannot load arbitrary remote URLs.
- Skins are declarative JSON + CSS + local assets. No JavaScript in level 1–2 skins.
- The built-in Clarity skin must always be available as a fallback.
- Use English for UI strings, code comments, commit messages and documentation.
- Keep production dependencies pinned exactly; do not use `latest`.

## Continuous integration

`.github/workflows/ci.yml` runs on an `archlinux:base-devel` container. It installs the system and Go toolchain, then runs:

1. `npm ci`
2. `npm run check`, `npm run lint`, `npm run format`, `npm run test`, `npm run build`
3. Filtered `go test` and `go vet`
4. `wails3 build`

Packaging and release automation are added in M4.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `wails3: command not found` | Add `$(go env GOPATH)/bin` to `PATH` |
| `pattern all:frontend/dist: no matching files found` | Run `npm run build` in `frontend/` before Go commands |
| Vite port already in use | Stop the other Vite process or set `WAILS_VITE_PORT` |
| Window is tiled on Sway/i3 | Add the floating rule above |
| WebKitGTK rendering issues | Try `WebviewGpuPolicyNever` to isolate the GPU driver |
| Skin is missing from the library | Check its warning in the library; confirm the directory name matches the manifest `id` |
| Skin CSS is not applied | Confirm `styles.css` is at the package root and its URLs resolve to local assets |
| Third-party skins are disabled | Restart without `--safe-mode` and enable them in the skin library |
| Spotify says `No active device` | Open the official Spotify client and start playback; then select the device in Cadence |
| Spotify login cannot bind port 43821 | Close the process using the port; the redirect URI is fixed by design |
| Keyring unavailable | Start/unlock GNOME Keyring or another Secret Service provider |
