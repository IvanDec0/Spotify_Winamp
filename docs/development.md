## Commands

Run commands from the repository root. The Taskfile is Linux-only.

| Command | Purpose |
|---|---|
| `task dev` | Start the Wails development loop with Vite HMR |
| `task build` | Build the production frontend and `bin/cadence` |
| `task audio:build` | Build the pinned go-librespot engine into `bin/go-librespot` |
| `task run` | Run the built binary |
| `task test` | Build the frontend, run Go tests and Vitest |
| `task check` | Run Go vet, `svelte-check`, ESLint and Prettier |
| `task lint` | Run Go vet, ESLint and Prettier |
| `task format` | Check Go and frontend formatting |
| `task format:write` | Format Go and frontend sources |
| `task package` | Create AppImage, tar.gz (with the engine) and checksums in `bin/` |
| `task clean` | Remove build outputs and generated bindings |

The frontend scripts can also be run directly from `frontend/`:

```bash
npm ci
npm run check
npm run lint
npm run format
npm run test
npm run build
```

## Generated files

The following paths are generated and ignored by Git:

- `frontend/dist/` — Vite production bundle embedded into the Go binary.
- `frontend/node_modules/` — npm dependencies.
- `bin/` — compiled binary, audio engine and release artifacts.
- `build/linux/cadence.desktop` and `build/linux/appimage/build/` — packaging outputs.

`bin/go-librespot` is built locally with `task audio:build` and is not committed. Cadence discovers the engine from `CADENCE_GO_LIBRESPOT`, `PATH`, the directory next to the Cadence binary, or `bin/go-librespot` in the repository root.

`frontend/bindings/` is generated by Wails from the Go services and is committed so a fresh checkout can type-check without a prior build. Regenerate it with:

```bash
wails3 generate bindings -clean=true -ts -i .
```

The binding generator is given the main package explicitly. It walks the Go dependency graph, so services in `internal/` packages are included without scanning `frontend/node_modules`.

## Go tooling note

An npm dependency ships a small Go package. A plain `go test ./...` therefore also visits `frontend/node_modules`. The Taskfile and CI filter that directory:

```bash
go test $(go list ./... | grep -v '/node_modules/')
go vet $(go list ./... | grep -v '/node_modules/')
```

Use `task test` and `task check` for the supported workflow.

## Wayland and Sway

Cadence is frameless and relies on its custom titlebar for dragging. Tiling compositors ignore the requested window size, so add a floating rule for the application ID (840×440 is the 200%-scaled base window):

```text
for_window [app_id="io.github.ivandec0.cadence"] floating enable
for_window [app_id="io.github.ivandec0.cadence"] resize set 840 440
```

The app sets `WebviewGpuPolicyOnDemand` for WebKitGTK. If rendering is broken on a particular driver, set `WebviewGpuPolicyNever` temporarily to isolate the issue.

### Native window resizing

Wails v3 beta.34 maps `Window.SetSize` to `gtk_window_set_default_size` on GTK4, which does not resize an already mapped window. The queue expansion therefore calls `internal/platform.WindowService`, a small cgo GTK4 helper that sets both a size request and the default size on the GTK main thread. The helper receives physical pixels: the logical 420×220 design is multiplied by the 2× UI scale. If a later Wails release provides a real resize operation, remove the helper and the generated platform binding.

### UI scale

The webview keeps the original compact 420×220 logical layout and rescales it to the native window. The default is 200%, with a supported range of 125%–300%. Resizing the window changes the zoom so the current logical view fits; opening the Library or queue also fits the window to the screen work area.

The scale is coordinated in two places:

- `uiScale`, `minUiScale` and `maxUiScale` in [`main.go`](../main.go) configure the initial Wails window, minimum/maximum native size and initial zoom.
- [`frontend/src/lib/layout.ts`](../frontend/src/lib/layout.ts) contains the same range and the fit calculation used by `App.svelte` when the window is resized.

Skins keep authoring against the 420×220 logical space.

## Skin development

Development skins live in `skins-dev/<id>/`. Cadence scans that directory automatically when it runs from the repository root. Use `--skins-dev <dir>` for another location.

```bash
./bin/cadence --skins-dev ./skins-dev
./bin/cadence --safe-mode
./bin/cadence --demo
```

Manifest, layout, CSS and asset failures appear as warnings in the skin library. Restart Cadence after editing a development skin; packages are validated and scanned at startup. The included [`skins-dev/afterglow`](../skins-dev/afterglow) is a complete level 2 example.

Installed skins are stored under `$XDG_DATA_HOME/cadence/skins/<id>/`; settings are in `$XDG_CONFIG_HOME/cadence/config.json`. The built-in Clarity skin is native, cannot be removed, and is used when a declarative skin cannot be validated or mounted.

See [`skin-format.md`](skin-format.md) and [`skin-authoring.md`](skin-authoring.md).

## Spotify development

Cadence plays Spotify through **go-librespot**, a separate local audio engine. The app never embeds audio decoding and never asks the official Spotify client to play.

Build the pinned engine into `bin/go-librespot`:

```bash
sudo pacman -S --needed libogg libvorbis flac mpg123 alsa-lib libpulse
task audio:build
```

Run the app:

```bash
./bin/cadence            # local engine + Library panel
./bin/cadence --demo     # simulated player, no engine
```

Open the provider badge in the titlebar to show the Library. On first run the engine prints a pairing code; approve it at `spotify.com/pair`. The engine stores its credentials in `$XDG_CONFIG_HOME/cadence/audio/state.json` with owner-only permissions. Cadence receives only token-free state.

The engine writes its log to `$XDG_CACHE_HOME/cadence/logs/go-librespot.log`. Its loopback API binds to a random port on `127.0.0.1`, and the port is written into `$XDG_CONFIG_HOME/cadence/audio/config.yml`.

Useful flags:

```bash
./bin/cadence --demo   # start with the simulated player even if the engine is paired
```

Tests for the engine integration use `httptest` servers and do not need Spotify credentials. Live pairing, local playback and library browsing were verified manually on Arch Linux. The engine requires Spotify Premium and a working PulseAudio/PipeWire sink.

## Architecture rules for v1

- The frontend never receives Spotify playback credentials.
- go-librespot credentials stay in the engine's `state.json`; the frontend only sees token-free engine state.
- The demo provider remains available through `--demo`.
- Audio playback is owned by the engine process, not the webview and not the official Spotify client.
- Album art is proxied/cached through Go; skins and CSS cannot load arbitrary remote URLs.
- Skins are declarative JSON + CSS + local assets. No JavaScript in level 1–2 skins.
- The built-in Clarity skin must always be available as a fallback.
- Use English for UI strings, code comments, commit messages and documentation.
- Keep production dependencies pinned exactly; do not use `latest`.

## Continuous integration

`.github/workflows/ci.yml` runs on an `archlinux:base-devel` container. It installs the system and Go toolchain, then runs:

1. `npm ci`
2. `npm run check`, `npm run lint`, `npm run format`, `npm run test`, `npm run build`
3. Filtered `go test` and `go vet`
4. `wails3 build`
5. On `main` or manual dispatch, `task package` and uploads the release artifacts

`.github/workflows/release.yml` builds the same artifacts on a `v*` tag and publishes a GitHub release. The tag must match `version` in `build/config.yml`.

`task package` builds the engine with `task audio:build` when it is missing, bundles `go-librespot` in both artifacts and writes SHA-256 checksums. Packaging requires the audio CGO libraries listed in [`installation.md`](installation.md).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `wails3: command not found` | Add `$(go env GOPATH)/bin` to `PATH` |
| `pattern all:frontend/dist: no matching files found` | Run `npm run build` in `frontend/` before Go commands |
| Vite port already in use | Stop the other Vite process or set `WAILS_VITE_PORT` |
| Window is tiled on Sway/i3 | Add the floating rule above |
| WebKitGTK rendering issues | Try `WebviewGpuPolicyNever` to isolate the GPU driver |
| Skin is missing from the library | Check its warning in the library; confirm the directory name matches the manifest `id` |
| Skin CSS is not applied | Confirm `styles.css` is at the package root and its URLs resolve to local assets |
| Third-party skins are disabled | Restart without `--safe-mode` and enable them in the skin library |
| `Local audio engine unavailable` | Run `task audio:build` or set `CADENCE_GO_LIBRESPOT` |
| No pairing code | Restart the engine from the Library panel; check the engine log |
| Pairing code expired | Select **Reset pairing** and use the new code |
| No sound | Check that PipeWire/PulseAudio is running and the default sink is correct |
| Engine exits immediately | Run `bin/go-librespot --config_dir ~/.config/cadence/audio` manually to see its output |
