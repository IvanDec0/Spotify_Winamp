## Commands

Run commands from the repository root. The Taskfile is Linux-only.

| Command | Purpose |
|---|---|
| `task dev` | Start the Wails development loop with Vite HMR |
| `task build` | Build the production frontend and `bin/cadence` |
| `task run` | Run the built binary |
| `task test` | Build the frontend, run Go tests and Vitest |
| `task check` | Run Go vet, `svelte-check`, ESLint and Prettier |
| `task lint` | Run Go vet, ESLint and Prettier |
| `task format` | Check Go and frontend formatting |
| `task format:write` | Format Go and frontend sources |
| `task package` | Create AppImage, tar.gz and checksums in `bin/` |
| `task clean` | Remove build outputs and generated bindings |

The frontend scripts can also be run directly from `frontend/`:

```bash
npm ci
npm run check
npm run lint
npm run format
npm run test
npm run build
```

## Generated files

The following paths are generated and ignored by Git:

- `frontend/dist/` — Vite production bundle embedded into the Go binary.
- `frontend/node_modules/` — npm dependencies.
- `bin/` — compiled binary and release artifacts.
- `build/linux/cadence.desktop` and `build/linux/appimage/build/` — packaging outputs.

`frontend/bindings/` is generated by Wails from the Go services and is committed so a fresh checkout can type-check without a prior build. Regenerate it with:

```bash
wails3 generate bindings -clean=true -ts -i .
```

The binding generator is given the main package explicitly. It walks the Go dependency graph, so services in `internal/` packages are included without scanning `frontend/node_modules`.

## Go tooling note

An npm dependency ships a small Go package. A plain `go test ./...` therefore also visits `frontend/node_modules`. The Taskfile and CI filter that directory:

```bash
go test $(go list ./... | grep -v '/node_modules/')
go vet $(go list ./... | grep -v '/node_modules/')
```

Use `task test` and `task check` for the supported workflow.

## Wayland and Sway

Cadence is frameless and relies on its custom titlebar for dragging. Tiling compositors ignore the requested 420×220 size, so add a floating rule for the application ID:

```text
for_window [app_id="io.github.ivandec0.cadence"] floating enable
for_window [app_id="io.github.ivandec0.cadence"] resize set 420 220
```

The app sets `WebviewGpuPolicyOnDemand` for WebKitGTK. If rendering is broken on a particular driver, set `WebviewGpuPolicyNever` temporarily to isolate the issue.

## Architecture rules for v1

- The frontend never receives Spotify access tokens, refresh tokens or PKCE values.
- Album art is proxied/cached through Go; skins and CSS cannot load arbitrary remote URLs.
- Skins are declarative JSON + CSS + local assets. No JavaScript in level 1–2 skins.
- The built-in Clarity skin must always be available as a fallback.
- Use English for UI strings, code comments, commit messages and documentation.
- Keep production dependencies pinned exactly; do not use `latest`.

## Continuous integration

`.github/workflows/ci.yml` runs on an `archlinux:base-devel` container. It installs the system and Go toolchain, then runs:

1. `npm ci`
2. `npm run check`, `npm run lint`, `npm run format`, `npm run test`, `npm run build`
3. Filtered `go test` and `go vet`
4. `wails3 build`

Packaging and release automation are added in M4.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `wails3: command not found` | Add `$(go env GOPATH)/bin` to `PATH` |
| `pattern all:frontend/dist: no matching files found` | Run `npm run build` in `frontend/` before Go commands |
| Vite port already in use | Stop the other Vite process or set `WAILS_VITE_PORT` |
| Window is tiled on Sway/i3 | Add the floating rule above |
| WebKitGTK rendering issues | Try `WebviewGpuPolicyNever` to isolate the GPU driver |
